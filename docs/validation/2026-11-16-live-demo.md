# Live demo, first run: 2026-11-16

Issue #73, run 1 of the [planned runs](README.md#planned-runs-toward-the-30-day-backfill).
The default `docker compose up` stack against the live provider, on a fresh session
(old sessions, schemas and the Kafka backlog were wiped first). It found two bugs, fixed
in #99 and #100, and was then rebuilt and checked again.

## Scope

- USDC (`EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v`), finalized LaserStream,
  60-second live cycles, a 50-slot LaserStream replay (470384846–470384895), keep the
  newest 1,000 transfers. Archive enabled but not used: replay covered the range.
- Not run: Old Faithful archive batches, the archive-to-live seam (#31), any range
  longer than 50 slots, hosted PostgreSQL. Coverage was not verified.

## Command and environment

`docker compose up --build -d` with the `.env.example` defaults, at `9a9e2cd`; then
rebuilt at `462451b` and started once with `INDEXER_UPGRADE_BINARY=1`. Apple Silicon,
Docker Engine 29.9.2, local PostgreSQL 18.6 and Kafka 4.1.1 containers, one consumer,
six-partition `live-raw` topic.

| Coverage | `unknown`, verified boundary null | Same |

Consumer throughput roughly matched live input, so the consumer kept up on local
PostgreSQL. The [hosted measurement](2026-11-14-kafka-consumer-throughput.md) stays
below the USDC load.

## Cost

LaserStream usage for about 15 minutes of live intake and one 60 s replay grant
(11.5 MB). Credits were not read from the provider dashboard.
