# USDC live load measurement

Measured 2026-11-13 from the retained provider-backed Docker runtime session
(Apple Silicon, Linux ARM64 container, SQLite). This is a load estimate for
sizing infrastructure, not a capacity benchmark or a completeness claim.

## Dataset

96 consecutive live cycles from `events.jsonl` `live_metrics` events: USDC mint
filter, finalized LaserStream, 25,445 slots, 662,509 matched transaction attempts,
about 1.9 wall-clock hours. The runtime was catching up behind the tip, so rates
are derived per slot advanced between cycle-end events, not per wall second.
Per-second figures assume 0.4 s slots; slot time was not measured.

The transfers-per-transaction ratio comes from the 15 slots (469106154–469106168)
left after count-based pruning: 1,000 stored transfers, 396 of them USDC, from 193
signatures. Treat that ratio as a small-sample estimate.

## Results

| Measure | Value |
| --- | --- |
| Matched transactions per slot | mean 32.2, median 28.4, p90 46.6, max 186.3 |
| Matched transactions per second (0.4 s slots) | mean ~80, p90 ~117, peak slot ~465 |
| Protobuf bytes per transaction | 9,313 (received bytes, not billed bytes) |
| Decode failures | 0.91% of attempts |
| Raw write / decode+write per transaction | 0.81 ms / 3.88 ms (single consumer, SQLite) |
| Transfers per transaction | ~2.05 USDC; ~5.2 all mints in matched transactions |

## Derived estimates

- One sequential consumer sustains roughly 210 transactions/s (4.7 ms each). Mean
  load uses ~40% of that; bursts exceed it, and the session ended ~3,500 slots
  behind the reference tip. Parallel consumers are needed for bursts and catch-up.
- Transfer writes: ~160 USDC rows/s, ~415 rows/s for all mints in matched transactions.
- 30-day rows: ~415 million USDC-only, ~1.1 billion all mints.
- Raw retention: ~64 GB/day, ~1.9 TB per 30 days before compression.
- Provider usage: ~39 million credits/month at 2 credits per 0.1 MB, if billed
  bytes match received protobuf bytes. Unverified against authoritative usage.

Decoded storage, PostgreSQL sizing, compression ratios and time-of-day variation
were not measured.

## Reproduce

Inspect the stopped runtime volume read-only:

```sh
docker compose --profile live run --rm --no-deps --entrypoint python3 runtime -c "
import json, statistics as st
ev = [json.loads(l) for l in open('/app/data/runtime/events.jsonl') if 'live_metrics' in l]
rows, prev = [], None
for e in ev:
    if prev and e['slot'] and e['slot'] > prev:
        rows.append((e['metrics']['indexer_transactions_total'], e['slot'] - prev))
    prev = e['slot']
per_slot = [t / d for t, d in rows]
print(len(rows), sum(d for _, d in rows), st.mean(per_slot), st.median(per_slot))
"
```

Transfer ratios: `SELECT slot, count(*), count(DISTINCT signature) FROM transfers GROUP BY slot`
and `SELECT mint, count(*) FROM transfers GROUP BY mint` on the same session database.
